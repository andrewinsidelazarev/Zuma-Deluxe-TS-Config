# Claude Session Memory — ZUMA DELUXE — 2026-05-01

## Что было сделано

### Требование пользователя
Лягушка должна находиться по центру экрана и вращаться:
- курсором мыши, **или**
- клавишами O/P

### Изменения в `zuma_new.asm`

**1. Позиция лягушки → центр экрана (164, 128)**
- Экран 360×288, центр = (180, 144). Спрайт 32×32, top-left для центра = (180−16, 144−16) = (164, 128).
- `InitGame`: `LD HL, 164 : LD (FrogX), HL` / `LD HL, 128 : LD (FrogY), HL`
- Данные `FrogX: DW 164`, `FrogY: DW 128`
- `MouseAbsX/Y` → 220/144 (стартовая позиция курсора правее лягушки → начальный угол=0).

**2. Обработка клавиш O/P в `HandleInput`**
- Порт #DFFE: O=бит 1, P=бит 0 (активный=0).
- O нажата → `FrogAngle -= ROTATION_SPEED` (=4).
- P нажата → `FrogAngle += ROTATION_SPEED`.
- Чтение порта один раз в `E`, потом отдельные `BIT` проверки (порт читается только один раз — `IN` имеет побочный эффект, но для клавиш не важно; экономия — для красоты).

**3. Порядок в `MainLoop`**
- Было: `HandleInput` → `HandleMouse`. Из-за этого `ComputeFrogAngle` (из `HandleMouse`) затирал угол, выставленный клавишами.
- Стало: `HandleMouse` → `HandleInput`. Клавиши имеют приоритет над мышью (если нажата O/P, угол перезаписывается после мыши).

### Итерация 2 — фикс O/P (поворот только на 1 кадр)

**Симптом:** O/P поворачивали лягушку, но угол сразу возвращался обратно (видимый эффект — поворот «на 1 кадр»).

**Причина:** `HandleMouse` каждый игровой кадр вызывал `ComputeFrogAngle`, который пересчитывал угол по позиции курсора и затирал результат `HandleInput`. Курсор не двигался → угол всегда устанавливался один и тот же.

**Фикс:** добавил флаг `MouseMoved`:
- В `HandleMouse` сбрасывается в 0 в начале, взводится в 1 при ненулевой дельте по X или по Y.
- `ComputeFrogAngle` вызывается через `CALL NZ` — только если мышь реально двигалась.
- Когда мышь стоит, угол управляется только клавишами O/P → накопление работает.

**Дополнительно:** добавлена переменная `MouseMoved: DB 0` в данные.

**Сборка:** 0 errors, 1030 строк, `zuma_game.sna` пересобран.

### Итерация 3 — спрайт курсора прицела

**Решение архитектуры:** пользователь подтвердил — у TS-Config 4 МБ ОЗУ, лягушку не сокращаем. Курсор положим в **отдельную страницу 7** (следующая после жабы в SGPAGE=6). TNUM может выходить за SGPAGE — TSU читает ковёр последовательно по страницам (подтверждено учебником: «если у нас в памяти страничка за страничкой загружены последовательно спрайты, то нам не надо щелкать страничками»).

**Файлы:**
- `convert_cursor.py` — обрезает курсор.png по непрозрачному bbox (260,142..1005,935 → 745×793), ресайз до 16×16, квантизация в 16 цветов (0=прозрачный), 4bpp tile-формат, палитра в CRAM-формате для SPAL=1.
- `cursor_gfx.bin` — 4096 байт (2 тайл-строки страницы 7 = достаточно для 16×16 спрайта в верхнем-левом углу).
- `cursor_pal.bin` — 32 байта (16 CRAM записей для SPAL=1).

**Изменения в `zuma_new.asm`:**
1. Добавлены константы `SPSIZ16=#02`, `SPSIZ32=#06`, `SPACT=#20` (биты ACT и размера в SFILE).
2. Дескриптор курсора в SFILE по адресу `#0308` — после жабы (#0200) и 32 шаров (#0208..#0300). Размер 16×16, TNUM=512 (первый тайл страницы 7), SPAL=1.
3. Функция `UpdateCursorSprite` — обновляет дескриптор по `MouseAbsX/Y` каждый кадр.
4. Вызов `CALL UpdateCursorSprite` в `MainLoop` после `UpdateBallSprites`.
5. `InitPalette` загружает `cursor_pal.bin` в CRAM #0020..#003F (записи 16-31, SPAL=1) после frog_pal.
6. `INCBIN "cursor_gfx.bin"` в `SLOT 1 : PAGE 7 : ORG #4000`.

**Грабли при сборке:**
- `OR (SPACT | SPSIZ16)` → `Illegal instruction (can't access memory)` — sjasmplus трактует круглые скобки как косвенную адресацию. Замена на `OR SPACT+SPSIZ16` (через `+` без скобок).

**TNUM в дескрипторе курсора:**
- TNUM=512 → `TNUM_L = 0`, `TNUM_H = 2` (биты 8-11 = #02).
- SPAL=1 в битах 4-7 = #10.
- 5-й байт дескриптора = TNUM_H | (SPAL<<4) = #02 | #10 = **#12**.

**Сборка:** 0 errors, 1087 строк, `zuma_game.sna` пересобран. Включает frog_pal.bin (512), cursor_pal.bin (32), frog_gfx.bin (16384, page 6), cursor_gfx.bin (4096, page 7).

**Если курсор не виден после теста — что проверять:**
- TSU читает спрайт-ковёр поверх границы страниц или нет (подтверждение учебника есть, но эксперимент покажет).
- Палитра CRAM SPAL=1: формат байт верный? (взят из `convert_frog.py` — там работает для SPAL=0).
- Z-order: курсор имеет максимальный индекс в SFILE (#0308) — должен быть сверху.
- Координаты `MouseAbsX/Y` могут быть за пределами экрана при старте? Сейчас инициализированы (220, 144) — посередине.

## Что отложено

### `курсор.png` (1024×1024 RGBA, 1.27 MB)
Пользователь добавил классическую стрелку мыши в `c:\z80\zuma\курсор.png`. Картинка в формате 1024×1024 — это рендер увеличенного курсора. Нужно:

1. Найти bbox реального курсора в PNG (вероятно ~600×600 пкс на белом фоне).
2. Решить целевой размер спрайта: 16×16 или 32×32 пкс.
3. **Проблема памяти TSU:** SGPAGE=6 уже занята лягушкой целиком (16384 байт = 32 кадра × 16 тайлов × 32 байта). Курсор негде разместить как TSU спрайт без переделки лягушки.

**Возможные подходы:**
- (A) Уменьшить лягушку до 16 кадров (по 22.5°) → освободится полстраницы. Но качество вращения хуже.
- (B) Курсор как тайл на T1-слое (второй тайл-слой, сейчас не используется) — двигать через T1XOFS/T1YOFS.
- (C) Курсор через line interrupt + переключение SGPAGE — сложно.
- (D) Простой DOS-курсор: малевать через карту тайлов T0 (стирать предыдущую позицию, рисовать новую) — не TSU.

Решение принимать с пользователем — пока курсор работает только как невидимый «прицел» через `MouseAbsX/Y` (для угла лягушки).

## Контроль клавиш — нюанс

Сейчас, если двигать мышь, `ComputeFrogAngle` каждый кадр пересчитывает угол. Если **одновременно** нажать O/P, угол всё равно перезапишется клавишей (потому что HandleInput идёт после HandleMouse). Но если отпустить O/P, мышь снова возьмёт управление в следующем же кадре.

Это нормально для требования «или мышь, или клавиши». Если потребуется явное переключение режимов — добавить флаг `InputMode` (mouse/keyboard) и переключать его по факту движения мыши/нажатия клавиш.
